# Instant Navigations 도입 — 검토와 현황

Next.js 16.3의 [Instant Navigations](https://nextjs.org/blog/next-16-3-instant-navigations)
(`cacheComponents` + `partialPrefetching`) 도입을 검토하고, 3단계 중 2단계까지
진행한 기록이다.

---

## 1. 이 플래그가 실제로 요구하는 것

`cacheComponents: true`를 켜면 규칙이 하나 생긴다. **서버에서 `await`하는
데이터는 반드시 셋 중 하나여야 한다.**

- `<Suspense>`로 감싸 **스트림** — 로딩 셸을 즉시 보여준다
- `'use cache'`로 **캐시** — 이전 결과를 즉시 보여준다
- `export const instant = false`로 **블록** — 이 라우트는 포기한다고 선언한다

셋 다 아니면 개발 중 에러다. 즉 "켜면 빨라지는 플래그"가 아니라
**앱 구조를 바꾸라는 요구**다.

## 2. 검토 시점의 상태 (2026-08-15)

```
Suspense 사용:   0곳
loading.tsx:     0개
```

모든 라우트가 세션(쿠키)과 DB를 `await`했고, **루트 레이아웃이 쿠키·헤더를
읽어** 트리 최상단이 요청 시점에 묶여 있었다. 이 상태로 플래그를 켜면 모든
라우트가 한꺼번에 에러로 뜬다 — 고칠 게 적어서가 아니라 아무것도 안 되어
있어서다.

## 3. 단계로 나눈 이유

1~2단계는 **플래그와 무관하게 값어치가 있고**, 동시에 3단계의 전제 조건과
정확히 같은 작업이다. 그래서 어느 쪽을 택하든 낭비가 아니다.

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| **1** | Suspense 경계 (플래그 없이) | **완료** |
| **2** | 루트 레이아웃의 요청 시점 의존 제거 | **완료** |
| **3** | `cacheComponents` / `partialPrefetching` | **보류** |

### 1단계에서 한 것

- 홈은 월 이동 바를 Suspense 밖에 두어 먼저 그리고 목록만 스트리밍.
  `searchParams`도 안쪽에서 풀어야 한다 — 바깥에서 `await`하면 네비게이션까지
  함께 멈춘다
- **자리표시자(스켈레톤)는 두지 않는다.** 처음엔 라우트별 `loading.tsx`와
  스켈레톤 UI를 만들었는데, 지금 디자인에 없던 요소라 오히려 레이아웃 시프트를
  일으켰다. 경계만 남기고 `fallback`은 비웠다 — 값어치가 있던 것은 스트리밍
  구조였지 자리표시자가 아니었다.

곁다리로 하나 고쳤다. `CommitListNav`가 `useSearchParams()`를 쓰는데 Suspense
경계가 없어 **서버에서 렌더되지 않고 클라이언트로 빠지고 있었다.** 셸에 넣으려던
바로 그 컴포넌트가 셸에 못 들어가고 있었다.

### 2단계에서 한 것

루트 레이아웃이 `getServerTimezone()`으로 쿠키·헤더를 읽던 것을 제거했다.
확인해 보니 **그 쿠키를 심는 곳이 어디에도 없어서** 값은 늘 Vercel IP
추정값이거나 기본값이었다 — 비용만 내고 이득은 못 받고 있었다.

타임존은 브라우저만 확실히 아니까 방향을 뒤집었다. 클라이언트가 직접 알아내
쿠키에 남기고, 서버는 월 경계 계산에 그것을 쓴다. 읽기만 하던 쿠키가 이제
의미를 갖는다.

`getServerTimezone`은 **Suspense 경계 안에서만** 불러야 한다. 함수 주석에
못박아 뒀다.

## 4. 3단계를 보류하는 이유

- **아직 기본값이 아닌 실험적 플래그다.** 향후 메이저에서 기본이 될 예정이라고
  예고돼 있으므로, 그때 가서 받아도 늦지 않다.
- 1~2단계와 성격이 다르다. 앞의 둘은 플래그와 무관하게 이득이지만,
  `cacheComponents`는 **켜는 순간 캐시 모델을 받아들이는 결정**이다.
- 이 앱에서 얻을 것이 제한적이다. 라우트 5개, 사용자 1명, 작은 Turso 쿼리다.
  SPA식 즉시 전환이 극적으로 체감되는 건 링크가 수십 개인 대시보드류다.

## 5. 나중에 3단계를 할 때

1~2단계가 끝났으므로 플래그를 켰을 때 남는 것은 **인증(`Session`)과 DB 조회**
정도일 것이다. 둘 다 이미 Suspense 안에 있으니, Instant Insights가 짚어주는
것만 처리하면 된다 — "캐시할 수 있다" 또는 "블록으로 선언해라".

세션은 사용자마다 다르고 메모 목록은 자주 바뀌므로 `'use cache'`로 얻을 것은
많지 않다. 대부분 스트림으로 두거나, 라우트에 따라 `instant = false`로
블록을 선언하는 쪽이 맞을 가능성이 높다.
